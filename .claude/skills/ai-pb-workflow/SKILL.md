# AI PB 팀 협업 절차

사용자는 개발 경험이 적은 2인 팀(옥경환 koreanchubby, 이유경 yukyung16)의 한 명이다. 저장소: `github.com/koreanchubby/ai-pb`, 앱: https://koreanchubby.github.io/ai-pb/

## 항상 지킬 것

- 먼저 저장소의 `docs/WORKFLOW.md`, `docs/STATUS.md`, `docs/PROJECT_BRIEF.md`를 읽는다. 이 문서가 기준이고, 이 스킬과 다르면 문서를 따른다.
- 쉬운 말로 설명하고, 사용자가 직접 눌러야 하는 것(로그인, 비밀번호, 라이선스·약관 동의, 저장소 공개 설정)은 한 단계씩 안내한다.
- `index.html`의 버튼·입력칸 id를 바꾸지 않는다. 파일 전체를 덮어쓰지 않고 필요한 부분만 고친다.
- `app.js`는 두 사람이 같이 쓰는 파일이다. 고치기 전에 사용자에게 알리고, STATUS.md에서 팀원이 같은 파일을 건드리고 있는지 확인한다. 겹치면 멈추고 알린다.
- main에는 기능 코드를 직접 커밋하지 않는다(예외: `docs/STATUS.md` 상태 갱신). 기능은 이슈에 적힌 브랜치에서 작업한다.
- 자기 PR을 스스로 Merge하지 않는다.
- `.env`, API 키, 비밀번호를 커밋하지 않는다.
- 새 기능·파라미터에는 근거(논문 또는 공식 실무 자료)를 남기고, 팀 결정은 `docs/DECISIONS.md` 맨 위에 기록한다.
- 사용자가 이름이나 이슈 번호를 말하지 않았으면 STATUS.md와 Issues를 보고 추정한 뒤, 추정했다고 밝힌다.

## 작업 시작 ("작업 시작", "시작할게")

1. main을 최신으로 받는다(Pull).
2. `docs/STATUS.md`를 읽고 팀원이 지금 하는 일과 건드리는 파일을 요약한다.
3. 해당 이슈의 할 일과 완료 기준을 쉬운 말로 요약한다.
4. STATUS.md에서 사용자 작업을 🟡 진행 중으로 바꾸고 날짜를 갱신해 main에 커밋·푸시한다.
5. 이슈에 적힌 이름으로 브랜치를 만들고 전환한다.
6. 첫 번째로 할 일을 제안한다.

## 작업 중 막힘

- 에러 메시지나 원하는 동작을 확인하고, 원인을 쉬운 말로 설명한 뒤 최소한으로 고친다.
- 계산 함수를 바꾸면 같은 입력에서 변경 전후 숫자를 기록해 둔다(PR에 필요).

## 작업 끝 ("작업 끝", "끝났어")

1. 바뀐 파일과 내용을 쉬운 말로 요약한다.
2. 앱을 실행해 점검한다: 9단계(승계 포함)·7단계(일반 자산관리) 경로 완주, 설문 미완료·전문가 승인 전 다음 버튼 잠금, 모바일 폭(약 390px) 화면.
3. 문제가 없으면 커밋·푸시하고, `.github/pull_request_template.md` 양식을 채워 PR을 만든다. 본문에 `Closes #이슈번호`.
4. STATUS.md에서 해당 작업을 🔵 리뷰 대기로 바꾼다.
5. 팀원에게 보낼 짧은 카톡 메시지(PR 링크 포함)를 써 준다.

## 팀원 PR 리뷰 ("PR 리뷰")

1. PR 브랜치를 받아 실행한다.
2. 위 "작업 끝" 2번 점검 항목과, 계산 변경 시 전후 숫자 기재 여부를 확인한다.
3. 문제가 있으면 PR에 쉬운 말로 코멘트를 남기고 사용자에게 요약한다.
4. 문제가 없으면 승인(Approve)하고 Merge한다. 연결된 이슈가 닫혔는지 확인한다.
5. STATUS.md에서 해당 작업을 ✅ 완료로 옮기고, 두 사람 모두 main을 다시 받으라고 안내한다.

## 주간 보고서 ("보고서")

- STATUS.md 완료 항목과 이번 주 사용자의 커밋·PR을 바탕으로 report.eyefeet.com 양식(수행결과, 마일스톤 미달성 이유)에 맞춰 초안을 쓴다. 사실만 쓰고, 하지 않은 일을 한 것처럼 쓰지 않는다.
