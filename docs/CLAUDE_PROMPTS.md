## ① 작업 시작할 때

```
github.com/koreanchubby/ai-pb 저장소로 작업 시작할게.
나는 [옥경환 / 이유경]이고, 오늘 할 일은 이슈 #[번호]야.
docs/WORKFLOW.md의 "작업 시작 전" 순서대로 진행해줘.
1. main을 최신으로 받아줘
2. docs/STATUS.md를 읽고 팀원이 지금 뭘 하는지, 어떤 파일을 건드리는지 알려줘
3. 이슈 #[번호]의 할 일과 완료 기준을 쉽게 요약해줘
4. STATUS.md에서 내 작업을 🟡 진행 중으로 바꿔서 커밋·푸시해줘
5. 이슈에 적힌 이름으로 새 브랜치를 만들어줘
나도 개발을 잘 몰라. 내가 직접 눌러야 하는 건 한 단계씩 알려주고,
app.js를 고쳐야 하면 고치기 전에 먼저 말해줘.
```

짧게: `ai-pb 작업 시작, 나는 [이름], 이슈 #[번호]`

## ② 작업 중 막혔을 때

```
이슈 #[번호] 작업 중이야. docs/PROJECT_BRIEF.md 원칙을 지키면서 이어서 해줘.
index.html의 id는 바꾸지 말고, 파일 전체를 덮어쓰지 말고 필요한 부분만 고쳐줘.
지금 상황: [에러 메시지나 하고 싶은 것]
```

## ③ 작업 끝날 때

```
이슈 #[번호] 작업 끝났어. docs/WORKFLOW.md의 "작업 끝난 후" 순서대로 해줘.
1. 바뀐 파일과 내용을 쉽게 요약해줘
2. 앱을 실행해서 9단계(승계)·7단계(일반) 경로, 버튼 잠금, 모바일 화면을 점검해줘
3. 문제 없으면 커밋·푸시하고, PR 템플릿을 채워 Pull Request를 만들어줘 (Closes #[번호])
4. STATUS.md에서 내 작업을 🔵 리뷰 대기로 바꿔줘
5. 팀원에게 카톡으로 보낼 짧은 메시지(PR 링크 포함)를 써줘
```

짧게: `ai-pb 작업 끝, 이슈 #[번호]`

## ④ 팀원 PR 리뷰할 때

```
팀원이 올린 Pull Request #[번호]를 리뷰해줘.
docs/WORKFLOW.md "4. 리뷰하는 사람" 기준으로
그 브랜치를 받아서 실행해 보고, 문제가 있으면 쉬운 말로 알려줘.
문제가 없으면 승인하고 Merge한 다음, STATUS.md를 ✅ 완료로 바꾸고
두 사람 모두 main을 다시 받으라고 알려줘.
```

짧게: `ai-pb PR #[번호] 리뷰해줘`
