# AI PB — Project Brief

> 두 팀원과 AI 도구가 공통으로 참고하는 기준 문서입니다. 기능을 바꾸기 전에 먼저 이 문서를 확인하고, 바뀐 결정은 `DECISIONS.md`에 기록합니다.

## 1. 앱 목적

어떤 고객이 오더라도 **고객 정보 → 목표 → 자산 진단 → 하우스뷰 → 포트폴리오 설계 → 절세 → (승계 시) 전문가 검토 → 최종 리포트**까지 PB 상담 흐름을 안내하는 **범용 AI PB(Private Banker) PWA 웹앱**입니다.

- 배포 주소: https://koreanchubby.github.io/ai-pb/
- 기준 화면: 인터랙티브 프로토타입 v4 (태그 `prototype-v4`)

## 2. 화면 흐름 (v4 기준)

| 단계 | 화면 | 핵심 내용 |
|---|---|---|
| 1 | 고객 정보·투자성향 | 연령, 현재 상태, 가족 구성. 투자성향은 10문항 설문(한 화면 한 문항)으로 자동 산출 |
| 2 | 목표 설계 | 일반 자산관리 / 은퇴 준비 / 자산승계 / 은퇴·승계 모두. 은퇴 선택 시 은퇴 시점·월 생활비·연금 |
| 3 | 자산 입력·진단 | 부동산, 국내·해외 주식 ETF, 국채, 회사채, 사모펀드(환매 가능 연도), 금·리츠, 현금, 부채, 반드시 보유할 거주 부동산 |
| 4 | 승계 사전진단 | 승계 포함 시에만. 희망 배분 vs 법정상속분·유류분, 상속세 단순 추정, 재원 마련 방식 비교 |
| 5 | 하우스뷰·시장근거 | 하우스뷰(데모 표기)와 시장 근거 공개, TAA(±2%p) 반영 여부 결정 |
| 6 | 포트폴리오 설계·실행 | 필수 안정자산 → 조정 불가 자산 → 성향별 모델로 SAA, 거래 목록·분할 실행·적합성 확인 |
| 7 | 절세 전략 | 금융소득종합과세 추정, 연금저축·IRP, ISA 등 검토 |
| 8 | 전문가 검토 | 승계 포함 시에만. 세무사·변호사 검토 상태와 승인 조건 반영 |
| 9 | 최종 리포트 | 목표, 적합성, 하우스뷰, 승인 조건, 최종 배분, 사후관리 계획 |
| 별도 | 뉴스 분석 (투자자 페이지) | 상담 단계와 별개. 뉴스 요약과 "내 자산 영향" |

- 일반 자산관리·은퇴 준비: 7단계 (4·8단계 생략)
- 자산승계·은퇴·승계 모두: 9단계

## 3. 화면 원칙 (교수님 피드백 반영)

- 모든 주요 화면 하단 오른쪽에 같은 크기·위치의 다음 버튼, 목적지 표시 ("다음 단계 · 포트폴리오 설계·실행")
- 하단 왼쪽 이전 버튼, 상단 현재 단계와 진행률
- 필수 조건 미충족 시 다음 버튼 잠금 (설문 미완료, 희망 배분 합계 ≠ 100%, 전문가 승인 전)
- 목표에 필요 없는 화면·질문은 건너뜀

## 4. 판단 경계 (가장 중요한 원칙)

| 주체 | 맡는 일 | 맡지 않는 일 |
|---|---|---|
| 계산 코드 (app.js) | 성향 채점, 배분, 상속세 단순 추정, 금융소득 추정 | — |
| AI (LLM) | 뉴스 요약, 사실과 해석 분리, 쉬운 설명 | 비중 숫자 결정, 법률·세무 결론 확정 |
| 전문가 (세무사·변호사) | 상속·증여 방식, 세무·법률 최종 판단 | — |
| 고객 | 최종 승인 | — |

## 5. MVP 범위

| 포함 | 나중으로 미룸 |
|---|---|
| v4 화면과 계산 엔진 그대로 배포 | 실명 인증, 금융기관 자동 연동 |
| 입력값 저장 (브라우저 저장부터) | 고객별 로그인·권한 |
| 목표별 조건부 이동, 설문 기반 성향 | 개별주식 분석, 실제 주문 |
| 규칙 기반 승계 위험 신호, 상속세 단순 추정 | 법률·세무 결론 자동 확정 |
| 뉴스 자동 수집과 AI 요약 (투자자 페이지) | 실시간 스트리밍, 푸시 알림 |
| 전문가 승인 상태 데모 | 실제 세무사·변호사 계정 |

## 6. 프로젝트 절대 원칙

- **모든 기능·파라미터·제약조건은 학술 논문 또는 공식 실무 자료에 근거**합니다. "편리할 것 같아서"는 근거가 아닙니다. 논문 근거가 없는 실무 관행은 "실무 표준"으로 구분해 표기합니다.
- 인용하는 논문은 저자·연도·제목·저널을 실제로 확인한 뒤 씁니다.
- 과제는 AI로 채점되므로 인용, 수식, 재현 가능한 코드, 명확한 데이터 형식을 갖춥니다.

## 7. 개발 도구와 규칙

- 도구: Google Stitch(디자인) · JetBrains WebStorm(코드) · GitHub(공동 원본) · GitHub Pages(배포)
- `index.html`의 버튼·입력칸 id는 바꾸지 않습니다 (app.js가 이 이름으로 요소를 찾음)
- 계산 함수를 바꾸는 PR에는 같은 입력에서의 변경 전후 숫자를 적습니다
- Stitch·AI가 만든 코드로 파일 전체를 덮어쓰지 않습니다
- main은 항상 실행 가능한 상태로 유지, 기능마다 브랜치, PR은 상대 팀원이 실행해 보고 승인
