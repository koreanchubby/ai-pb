## 2026-09-30 · 하우스뷰 구성 방식

- **결정**: 국내 메이저 증권사 여러 곳의 월간 하우스뷰를 자산군별 +1 / 0 / -1로 점수화해 **동일가중 합의**로 TAA 산출
- **근거**: 여러 전망을 결합하면 개별 전망보다 평균적으로 오차가 작다는 예측 결합 연구 (Bates & Granger, 1969; Timmermann, 2006 — 서지 재확인 필요). 한 곳만 쓰면 편향·선택 근거 설명이 어려움
- **규칙**
  - 보고서 원문·표·차트를 앱에 게시하지 않음 (증권사 저작권). 점수와 출처(기관명·자료명·발간일)만 사용
  - 참고 기관 목록은 고정 (결과 좋은 곳만 고르는 선택 편향 방지)
  - 의견이 크게 엇갈리는 자산(+1과 -1 공존)은 0 처리 후 "기관 간 의견 불일치" 표시
  - 관리자가 월 1회 수동 입력 (자동 크롤링 금지)
  - 실제 자료를 쓰기 전까지 "OO증권 리서치센터 (데모 예시)" 표기 유지
- **영향 파일**: `app.js`의 `HOUSE_VIEW`

## 2026-09-30 · 투자성향 산출 방식

- **결정**: 투자성향을 드롭다운으로 직접 고르지 않고 **10문항 설문 → 점수 → 5단계 자동 산출**
- **근거**: 실제 증권사는 투자자정보확인서 설문 점수로 성향을 정함 (금융투자협회 표준투자권유준칙 제8조). 예: 신한투자증권 11문항 56점 만점 → 16점 이하 안정형 / 17~24 안정추구형 / 25~32 위험중립형 / 33~40 적극투자형 / 41 이상 공격투자형
- **남은 일**: `SURVEY`·`surveyScore()`의 점수 구간은 현재 데모값 → 실제 채점표 기준으로 교체 후 출처 기록

## 2026-09-29 · 상속·증여 기능의 판단 경계

- **결정**: AI는 상속세 단순 추정과 위험 신호만 제시하고, 승계 방식은 세무사·변호사 검토 후 확정. 확정된 조건은 포트폴리오 설계에 다시 반영
- **근거**: 상속·증여는 단순 세율 계산이 아니라 평가방법·사전증여 합산·유류분 등 법률 판단이 걸림

## 2026-09-29 · 고객 정보 입력 분할

- **결정**: 한 화면에 몰아서 받지 않고 성격별로 분리 — 고객 정보·설문(선택형) / 목표(조건부 질문) / 자산 입력(금액)
- **근거**: 입력 피로도 감소. 가족 구성·자산 금액은 한 번만 받고 이후 단계에서 재사용

## 과목 요구사항과 평가 (교수님 강의자료·수업 안내)

- 결과물: PWA 웹앱 + 금융 AI 기능 (뉴스 분석 등). 2인 1조
- 진행 순서: 계획 PPT → 화면 시나리오 → 플로우 차트 → DB 설계 → 주요 함수 설명서 → 사용 설명서 → 라이브러리/API 정리 문서
- 매주 개인별 보고서 제출 (report.eyefeet.com, 4주차부터). 마일스톤 5개 이상 가산점
- 평가 배점: 출석 10 · 개인별 과제 10 (수행문서 13개, 제출·완료 1 / 부분 0~1 / 미제출 0) · 프로젝트 발표 10 (8개 항목) · 중간 30 · 기말 40 · 가산점 블룸버그 자격증 +2, 블룸버그 과제 +2 (최종 100점 상한)
- 수업 중 안내: 모든 기능은 논문에 근거해야 하며, 과제는 AI로 채점됨
